Returns `{ok:true}` ALWAYS on data issues (whole DB section try/catch — never 5xx). 400 only for invalid user / empty code.
- **src/app/api/scan-log/stats/route.ts** (NEW, GET): manager-gated GM|OM|IT_ADMIN|OWNER → 403 else (incl. missing/unknown/inactive userId). days clamp 1..90 default 7. findMany SCAN_IN audits since start-of-local-day N-1 days ago, reduced in JS; byDay pre-seeded with all N days ascending (zeros included); parses `| scan=` marker first, Persian-label regex fallback; GET writes nothing.
- **DeliveriesSection.tsx** (EDIT — scan-related parts only): `submit(rawOverride?, source='manual')` + resolve prop gains optional `source`; camera path calls `submit(raw,'camera')`; chips/Enter/button default 'manual' (chip re-opens ARE logged). `resolveScan(rawCode, source)` logs EVERY branch: hit→'hit', DONE→'closed', CANCELLED/not-yet→'warn', unknown code→'miss', lookup failure→'error' (see deviation 1). Manager stats chip in the scan-bar header (cream/gold gradient pill, thin #EAD9A8 border, 11px gold text «اسکن ۷ روز: N — موفق M» toFaDigits, 7-bar pure-div sparkline — olive bars, today gold, rounded tops, aria-hidden, 18%/12% min heights, camera-share badge «دوربین N٪», Persian tooltip). 2. «موفق» in the chip = hits + closed (a DONE-order scan did find and open the order); raw hits/closed are separate in the API.
